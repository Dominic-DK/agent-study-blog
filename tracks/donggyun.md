# 🛠 동균 — 개발 워크플로(메인 미션) & 국부펀드 Agent 공모전

> 목표 · 기간 · 학습방법은 **초안**입니다. 11/9 킥오프에서 같이 확정합니다.

**🎯 최종 결과물**: (킥오프 때 작성)

## 목표 (초안)

- **A. 개발 워크플로 (메인)**: 이슈 → 검증 → 개선 → 확인 → PR → 이슈 반영 흐름을 코딩 에이전트로 돌리기
- **B. 국부펀드 Agent 공모전**: 좁은 범위(국가 1 × 산업 1)에서 출처를 붙인 리포트를 내는 RAG 에이전트 MVP
- **완료 기준**
  - A — 이슈 1건을 처음부터 끝까지 흐름대로 처리한 시연 + 스킬 2개 + 전/후 시간 비교
  - B — 예상 질문 10개 답변 + 출처 일치 평가표

## A. 개발 워크플로 흐름

| 단계 | 에이전트가 하는 일 | 사람 확인 |
|---|---|---|
| 1. 이슈 읽기 | 이슈를 요구사항 · 완료 조건으로 정리 | ✅ 요구사항 합의 |
| 2. 샌드박스 검증 | 별도 브랜치 / worktree에서 문제 재현, 실패하는 테스트 작성 | |
| 3. 개선 | 수정 구현 | |
| 4. 개선 버전 확인 | 테스트 실행, 수정 전후 비교 | ✅ 결과 확인 |
| 5. PR 생성 | `gh pr create` (요약 + 이슈 링크) | ✅ 머지 |
| 6. 이슈 반영 | PR 링크 댓글 · 상태 변경 | |

- **스킬화**: 1단계는 `/issue-start`, 5~6단계는 `/issue-finish` 같은 스킬로 → 반복 절차를 스킬로 바꾸는 연습 + 사용량 절약
- **회사 이슈 시스템**: Jira · Redmine을 사내망에 두거나 API 토큰을 막아둔 경우가 많음 → 막혀 있으면 개인 GitHub 저장소 + GitHub Issues로 연습
- **B 저장소를 이 흐름으로 관리**: B의 작업을 이슈로 쪼개서 A의 흐름으로 처리하면, 회사 정책과 상관없이 A를 실전으로 연습하면서 B도 진행
- 「샌드박스」가 Claude Code의 샌드박스 기능을 뜻한다면 윈도우에서는 WSL2 필요. 브랜치 · worktree · Docker 같은 격리 환경이면 WSL 없이 가능

## B. 국부펀드 Agent 공모전

**RAG와 AI Agent를 활용하여 신흥국의 투자 기회를 탐색하고, 투자 판단에 필요한 국가·산업·정책·시장 정보를 통합 분석하는 서비스 구현**

### 핵심 시나리오

사용자가 "브라질의 핵심 광물 산업 투자 기회를 분석해 줘"라고 질문하면 다음 정보를 수집하고 분석한다.

- 국가별 경제 및 산업 현황
- 핵심 광물의 생산량 · 수출입 · 수요 및 공급 동향
- 정부의 산업 육성 정책 및 외국인 투자 규제
- 글로벌 시장 동향 및 관련 기업 정보
- 환율 및 거시경제 지표
- 투자 기회 및 주요 리스크 분석

### Agent 처리 흐름

사용자 질문 → 질문 분석 및 작업 분해 → 관련 자료 검색(RAG) → 외부 데이터 수집 → 정보 통합 및 분석 → 출처 기반 답변 생성 → 투자 판단 리포트 제공

| 단계 | 정할 것 |
|---|---|
| 데이터 수집 | 국가별 경제 보고서, 산업 보고서, 투자 정책, 시장 데이터, 환율 등 |
| 문서 전처리 | PDF 및 웹 문서 파싱, 텍스트 추출, 청킹 |
| 벡터 인덱싱 | Embedding 모델 선정, Vector DB 구축, 메타데이터 설계 |
| 검색(RAG) | 질문에 적합한 국가·산업·정책 관련 문서 검색 및 검색 품질 개선 |
| Agent 설계 | 질문 의도 분석, 검색 도구 선택, 외부 API 호출, 작업 흐름 제어 |
| 분석 및 생성 | 수집된 정보를 종합하여 투자 기회와 리스크 분석 |
| 결과 제공 | 근거 자료 및 출처를 포함한 투자정보 분석 리포트 |
| 평가 | 검색 정확도, 답변 신뢰도, 출처 일치 여부, 응답 시간 검증 |

### 산출물

- 국부펀드 투자정보 분석 AI Agent 프로토타입
- 국가·산업별 투자정보 데이터셋 및 Vector DB
- RAG 및 Agent 아키텍처 설계
- 투자정보 분석 결과 리포트
- 검색 및 답변 품질 평가 결과

### 범위 축소안 (도미닉 제안)

| 원칙 | 내용 |
|---|---|
| MVP를 좁게 | **국가 1 × 산업 1 × 질문 10개 × 문서 30개 정도** (예: 브라질 × 핵심 광물). 출처 정확도가 나오면 그다음에 확장 |
| 숫자는 API 도구로 | 환율 · 거시지표 · 수출입 통계는 벡터 DB가 아니라 공개 데이터 API를 호출하는 도구로 (예: World Bank, UN Comtrade) |
| 서술형 문서만 RAG | 정책 · 산업 보고서만 청킹 → 벡터 DB. 넣을 양이 크게 줄어듦 |
| 출처는 메타데이터로 | 청킹할 때 `문서명 / 페이지 / URL`을 같이 저장하고 답변에 청크 ID 인용. 이 규모면 pgvector로 충분 |

> ⚠️ **구독 ≠ 서비스 비용.** Claude 구독은 개발 도구(Claude Code) 비용이고, B 서비스가 모델 · 임베딩을 호출하는 비용은 별도(API 키 또는 로컬 모델). 공모전에서 데이터셋 · API 크레딧을 주는지 먼저 확인.

## 기간 (초안) — 공모전 마감일에 따라 조정

| 주차 | A. 개발 워크플로 | B. 공모전 |
|---|---|---|
| W1 (11/9~) | 설치 · 연습 저장소와 이슈 시스템 연결 · 회사 AI 정책 확인 | 공모전 규칙 확인 · 국가 × 산업 1개 · 예상 질문 10개 |
| W2 (11/16~) | 1~4단계: 이슈 → 실패 테스트 → 수정 → 확인 | 문서 30개 수집 · 청킹 · 메타데이터 · 미니 RAG |
| W3 (11/23~) | 5~6단계 + `/issue-start` · `/issue-finish` 스킬화 + 전/후 기록 | 출처 붙은 답변 v0 + 숫자 데이터 API 도구 1개 |
| W4 🎙 (11/30~) | 이슈 1건 처음부터 끝까지 시연 | v0 데모 + 질문 10개 1차 평가 → 에이전트 범위 확정 |
| W5 (12/7~) | 유지 · 보완 (B 이슈 처리에 계속 활용) | 에이전트화: 질문 분해 · 도구 선택(RAG vs API) |
| W6 🎙 (12/14~) | 정리 | 평가표(검색 정확도 · 출처 일치) + 데모 |

> 💡 **제안**: 둘을 따로 무겁게 돌리지 않기. A 흐름을 W1~W3에 완성하고, 그 흐름으로 B 저장소의 이슈를 처리하면 두 과제가 하나로 이어집니다. 공모전 마감이 12/20보다 빠르면 B 일정을 앞당기기.

## 학습방법 (초안)

- **만들면서 배우기**: 개념은 짧게 → 바로 작은 버전 → 매주 데모 가능한 상태 유지
- **RAG는 순서대로**: 미니 RAG(문서 30개) → 평가 → 에이전트화. 처음부터 큰 프레임워크로 시작하지 않기
- **백엔드 경험 활용**: 벡터 DB는 익숙한 DB 확장(예: PostgreSQL + pgvector)부터 검토
- **도미닉 지원**: 설계 리뷰 2회(W2 · W4), 코드 · 아키텍처 질문은 이슈로
