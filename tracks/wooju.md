## 목표 (초안)

- **메인**: 본인의 트렌드 감각(암묵지)을 규칙으로 꺼내고, 그 규칙으로 돌아가는 트렌드 발견 에이전트 만들기
- **완료 기준**
  1. 암묵지 정리본 `my-rules.md` (판단 기준 · 티핑포인트 신호)
  2. 자주 보는 곳 기반 소스 목록 + 리서치 자료 LLM wiki
  3. 시그널 분류 기법 2~3개 비교표
  4. **백테스트 순위표**: 본인이 예전에 발견한 트렌드가 몇 위에, 얼마나 일찍 나오는지
- **함께 얻을 것**: 사전 질문 2개의 답 — 「무엇을 AI에 맡기고 무엇을 사람이 할지」는 0단계와 3단계에서, 「구조를 어떻게 잡는지」는 1~2단계에서 직접 만들면서 감 잡기

## 흐름

| 단계 | 하는 일 | 사람 확인 |
|---|---|---|
| 0. 암묵지 인터뷰 | 수동으로 하던 루틴 · 스크랩해둔 자료 · 트렌드라고 확신한 이유 · 티핑포인트를 발견한 경험 · 틀렸던 경험을 인터뷰로 끌어내서 `my-rules.md`로 정리 | ✅ 본인이 규칙 검수 |
| 1. 소스 담기 | **자주 보는 곳 기준**으로 `sources.md` 작성, 기존 스크랩을 `raw/`에 모으기 | |
| 2. LLM wiki화 | `raw/` 자료를 키워드 · 브랜드 · 현상 단위 페이지로 정리, 서로 링크 + `index.md`. 새 자료가 들어오면 wiki 갱신 | ✅ 정리가 맞는지 |
| 3. 시그널 분류 | 여러 기법으로 분류해보고 결과 비교 (아래 표) | ✅ 본인 감과 비교 |
| 4. 백테스트 · 순위 | 규칙대로 과거 데이터를 모아 점수 · 순위 매기기 → 본인이 발견했던 트렌드가 나오는지 확인 | ✅ 결과 해석 |

## 0단계 — 암묵지 인터뷰

| 영역 | 질문 예시 |
|---|---|
| 루틴 | 트렌드를 찾을 때 실제로 어디를, 얼마나 자주, 어떤 순서로 보나요? 뭘 저장하나요? |
| 스크랩 | 스크랩해둔 것 중 「이거다」 싶었던 3개는? 왜 저장했나요? 어디에 모아뒀나요? |
| 확신 근거 | 트렌드라고 확신한 순간은? (여러 곳에서 동시에 보였다 · 특정 계정 · 댓글 반응 · 검색량 등) |
| 티핑포인트 | 처음 봤을 때와 다들 말하기 시작했을 때 사이에 어떤 신호가 있었나요? |
| 오판 | 트렌드인 줄 알았는데 아니었던 것은? 왜 틀렸나요? |
| 시점 | 위 사례들을 대략 언제 발견했나요? (백테스트에서 「얼마나 일찍」을 재는 기준) |

- **진행**: 도미닉이 30~45분 직접 인터뷰 → LLM 인터뷰어(인터뷰 스킬)로 빈 곳 보충 → 본인이 검수
- **0단계 결과가 4단계 정답지**: 여기서 나온 「발견한 트렌드 3~5개 + 시점」과 「오판 사례 1~2개」를 백테스트 정답 셋으로 씁니다
- 업무 면담으로 암묵지를 꺼내 규칙으로 만드는 건 실무 AX의 출발점과 같은 방법입니다

## 2단계 — LLM wiki 구조

| 구성 | 역할 |
|---|---|
| `raw/` | 원본 그대로 (스크랩 · 기사 · 캡처 메모). 수정하지 않음 |
| `wiki/` | LLM이 정리한 페이지: 키워드 · 브랜드 · 현상별 요약, 처음 본 날짜, 근거 링크, 관련 페이지 링크 |
| `wiki/index.md` | 전체 목차 · 페이지별 한 줄 요약 |
| 갱신(ingest) | 새 자료가 오면 관련 페이지를 고치거나 새로 만들기 → 스킬로 |
| 점검(lint) | 중복 · 모순 · 근거 없는 페이지 · 고립된 페이지 찾기 → 주기적으로 |

## 3단계 — 시그널 분류 기법 후보

| 기법 | 내용 | 비고 |
|---|---|---|
| 본인 규칙 루브릭 | 0단계에서 뽑은 판단 기준으로 LLM이 점수 매기기 | 가장 먼저 |
| 증가율 · 가속도 | 검색량 · 언급량이 평소 대비 얼마나 빨리 느는지 (기준선 대비 이상치) | 스크립트로 계산 |
| 확산 경로 | 커뮤니티 → SNS → 뉴스처럼 채널을 건너 퍼지는지, 출처가 다양해지는지 | 티핑포인트와 직접 연결 |
| KEM · KIM | 키워드의 노출 빈도(DoV)와 확산 정도(DoD)로 강신호 · 약신호 · 잠재신호 4분면 분류 | 국내 약신호 연구에서 많이 쓰는 방법 |
| 확산 단계 | 혁신 수용자 → 초기 수용자 → 초기 다수 중 어디인지 (Rogers 확산 이론) | 해석용 프레임 |
| STEEP | 사회 · 기술 · 경제 · 환경 · 정치 중 어떤 동인인지 | 해석용 프레임 |
| 임베딩 클러스터링 | 비슷한 신호끼리 자동으로 묶기 | 선택 |

전부 하지 않고 **2~3개만 골라서** 같은 데이터에 돌려보고 비교합니다. 본인 규칙 루브릭 + 숫자 기법 1개(증가율 또는 KEM · KIM) 조합을 추천.

## 4단계 — 백테스트 설계

| 항목 | 내용 |
|---|---|
| 정답 셋 | 0단계의 「본인이 발견한 트렌드 3~5개 + 시점」, 「오판 사례 1~2개」 |
| 데이터 | 공식 API 우선 (예: 네이버 데이터랩 검색어 트렌드 · 뉴스 검색, 유튜브 Data API). SNS 무단 스크래핑은 약관 문제 소지 |
| 범위 | 도메인 1개 · 과거 6~12개월 |
| 지표 | 정답 트렌드가 상위 N위 안에 드는지 · 본인보다 얼마나 일찍(또는 늦게) 잡는지 · 오판 사례를 걸러내는지 |

## 킥오프에서 나온 것 (11/10)

- **우주 목표**: 마케팅 영역에서 AI 에이전트를 쓸 수 있는 범위를 찾고 자동화하기. 특히 **시장 조사 → 인사이트 도출** 과정을 AI로 효율적으로
- **순서 확인**: ① 내 트렌드 감각이 어느 정도인지 ② 그 규칙을 말로 설명할 수 있는지 ③ AI에 똑같이 시켰을 때 비슷한 결과가 나오는지 ④ 어디까지 자동화되는지 → 위 0~4단계와 같은 흐름
- **⚠️ 주의**: LLM은 자료가 모일수록 비슷한 쪽으로 뭉치기 쉬워서 사람의 번뜩이는 아이디어는 잘 안 나옴. 리서치 · 수집 · 분류는 맡기고, **번뜩이는 주제를 고르는 건 사람 몫**으로 두면서 규칙으로 꺼낼 수 있는 만큼 자동화
- **백테스트 목표**: 수많은 키워드 · 트렌드 중에서 적절한 시점에 찾아내고 **이유까지** 찾는지
- **이번 주 숙제**: 11/13(금) 전까지 GitHub 가입 + Claude 구독

## 학습방법 (초안)

- **인터뷰로 시작**: 도구보다 본인 판단 기준을 먼저 꺼내기. 이후 모든 단계가 이 규칙을 기준으로 움직임
- **본인 감이 정답지**: 기법을 바꿀 때마다 결과를 본인 판단과 비교하고, 맞은 이유 · 틀린 이유를 기록
- **수집은 스크립트, 판단은 LLM**: 과거 데이터 수집은 스크립트로 ([20달러 원칙](../guides/usage-principles.md) 1번)
- **CLI로 시작**: 킥오프 직후 설치 세션을 같이 하고, 막히면 데스크톱 앱으로 시작했다가 CLI로 넘어오기
- **일요일 공유**: 그 주 결과물을 진행 로그에 → 도미닉 피드백
- **근거 링크 습관**: 링크 없는 주장은 wiki · 리포트에서 빼기
