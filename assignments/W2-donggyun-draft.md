## 과제 1. 설계 — 데이터가 머무는 자리 정하기 (1~2시간)

[이슈 #33](https://github.com/Dominic-DK/agent-study/issues/33)의 답을 만드는 과제예요.

1. Claude에게 지금 상태부터 조사시킵니다.

   > 「`@agent-study-blog/resources/w2-pack/donggyun/data-map.md`의 자료 지도 표를 같이 채우자. 먼저 내 저장소의 인제스트 코드와 문서 폴더를 읽고, 자료 종류별로 "지금 어디에 있나"와 문서 수를 조사해서 보여줘. "어디에 두는 게 맞나" 칸은 비워 둬. 그건 내가 정할게.」

2. 「어디에 두는 게 맞나」 칸은 **직접** 채웁니다. 읽을거리의 세 자리(RAG / 그때 검색 → 편입 / API 도구)를 기준으로.
3. RAG 목적 카드 다섯 칸을 채웁니다. 「넣지 않는 것」을 먼저 쓰세요.
4. 새 데이터의 경로를 그림으로 그립니다. 손그림 사진도 좋아요.
5. 채운 내용을 #33에 댓글로 올립니다. 「아직 못 정한 것」도 같이.

- ✅ **확인**: 자료 지도에서 「지금」과 「맞나」가 다른 줄이 몇 개인지 말할 수 있다

## 과제 2. 측정 + 맡기기 — 기준 점수를 이슈 흐름으로 재기 (4~5시간)

A(개발 워크플로 1~4단계)와 B(평가)를 한 번에 합니다. 「기준 점수를 재는 스크립트」를 이슈로 만들고, 그 이슈를 Claude에게 통째로 맡겨요.

**2-1. 정답 문서 정하기 (직접, 1시간)**

`eval-sheet.md`를 복사해서, 평가 질문 10개(#16)마다 「답이 들어 있는 문서와 쪽」을 직접 찾아 적습니다.

- 이 단계는 Claude에게 맡기지 않아요. 정답지를 만든 쪽이 채점도 하면 점수를 믿을 수 없습니다
- 숫자를 묻는 질문은 「도구 질문」으로 표시하고 인덱스 점수에서 뺍니다 (과제 1의 자리 구분과 이어져요)

**2-2. 이슈 올리기 (15분)**

`issue-eval-script.md`를 본인 저장소에 맞게 고쳐서 이슈로 올립니다. W1에 연습한 「요구사항 · 완료 조건 · 확인할 점」 형식 그대로예요.

**2-3. 맡기기 (2~3시간)**

`issue-run.md`의 순서를 따릅니다. 시작하기 전에 기록표에 시작 시각부터 적으세요.

| 단계 | 내가 멈춰서 볼 것 |
|---|---|
| 1. 이슈 읽기 | Claude가 정리한 요구사항이 내 의도와 같은가 |
| 2. 실패하는 테스트 | **멈춤.** 테스트가 완료 조건을 하나씩 검사하는가 |
| 3. 수정 | 테스트 파일을 건드리지 않았는가 |
| 4. 확인 | **바뀐 코드를 직접 읽는다** |

- 정해 둔 두 곳(2단계 뒤, 4단계) 말고 중간에 끼어든 횟수를 셉니다. 왜 끼어들었는지가 다음 지시를 고치는 재료예요
- 5~6단계(PR · 이슈 반영)는 W3에 합니다

**2-4. 재기 (30분)**

스크립트를 돌려서 `eval-sheet.md`의 「측정 1 — 기준」을 채웁니다.

- ✅ **확인**: 「검색형 ○/6, 심화형 ○/4」를 말할 수 있고, 기록표에 한 줄이 있다

## 과제 3. (여유 있으면) 진단 — 원인 하나 찾기 (2시간)

W1 로그에 적은 막힌 점(「특정 문서에만 있는 내용을 가져오지 못함」)을 봅니다.

1. 과제 2에서 3위 안에 못 든 질문 하나를 고릅니다.
2. `retrieval-diagnosis.md`를 1번부터 순서대로 확인합니다.
3. 걸린 단계를 찾으면 **한 가지만** 바꾸고 다시 잽니다 → `eval-sheet.md`의 「측정 2」

- 이번 주에 못 하면 W3으로 넘겨도 됩니다. 과제 1 · 2가 먼저예요
