# 📝 W2 과제 — 일 맡기고, 중간에 확인하고, 결과 받기

| 항목 | 내용 |
|---|---|
| 기간 | 11/17 (화) ~ 11/22 (일) |
| 걸리는 시간 | 우주 3~4시간 · 동균 6~7시간 (+ 선택 2시간) |
| 사용량 | 보통 (Sonnet으로 충분) |
| 제출 | 따로 없어요. 이슈 댓글과 일요일 진행 로그로 |

> 이번 주 목표는 하나예요. **Claude에게 일을 맡길 때, 순서를 내가 정하기.** 지시 → 되묻기 → 중간 확인 → 결과 → 검토. W1에서는 Claude가 하자는 대로 따라갔다면, 이번 주는 어디서 멈추고 무엇을 확인할지를 내가 정합니다.
>
> 순서는 두 분이 같고, 재료는 각자 다릅니다. 본인 칸만 보면 돼요 → [📈 우주](#wooju) · [🛠 동균](#donggyun)

먼저 Claude에게 「사이트 최신 내용 받아줘」라고 해서 이번 주 자료를 받으세요.

### 🧰 연습 — 가상 자료로 한 바퀴 (1시간) · [#34](https://github.com/Dominic-DK/agent-study/issues/34)

연습용 꾸러미가 사이트 저장소에 들어 있어요. 내용은 전부 **지어낸 가상 자료**라서 틀려도 괜찮습니다.

```
agent-study-blog/resources/w2-pack/wooju/
├── brief.md              ← 업무 지시서 (팀장이 주는 이슈)
├── raw-sample/           ← 스크랩 메모 6개 (가상)
├── sources-example.md    ← 결과물 형식 예시
└── report-format.md      ← 중간 보고 · 결과 보고 양식
```

**준비**: `study/` 폴더에서 Claude를 열고 → 「trend-agent/practice 폴더 만들어줘」

아래 순서대로 말해보세요. 왼쪽이 회사에서의 단계, 가운데가 Claude에게 하는 말이에요. `@`는 「이 파일을 봐라」는 대상 지정입니다.

| 단계 | Claude에게 (프롬프트 + 대상) | 확인할 것 |
|---|---|---|
| 1. 지시 전달 | 「`@agent-study-blog/resources/w2-pack/wooju/brief.md` 읽고, 네가 이해한 내용을 5줄로 다시 말해줘. 아직 작업은 시작하지 마.」 | 내가 생각한 일과 같은가 |
| 2. 되묻기 | 「시작하기 전에 나한테 확인할 것을 한 번에 하나씩 물어봐. 다 물어봤으면 "질문 끝"이라고 해줘.」 | 어떤 질문이 나오는지 적어두기 |
| 3. 자료 확인 | 「`@agent-study-blog/resources/w2-pack/wooju/raw-sample/` 안의 파일을 하나에 한 줄씩 정리해줘. 정보가 빠진 파일이 있으면 알려줘.」 | 빠진 정보를 찾아내는가 |
| 4. 계획 | 「어떤 순서로 할지 3~5단계로 보여줘. 내가 OK 하면 시작해.」 | 순서가 납득되는가 |
| 5. 수행 + 중간 보고 | 「1번 파일만 먼저 처리해서 표에 넣고 멈춰. `@agent-study-blog/resources/w2-pack/wooju/report-format.md`의 중간 보고 형식으로 알려줘.」 | 첫 줄이 형식에 맞는가 |
| 6. 이어서 | 「좋아, 나머지도 같은 방식으로. 끝나면 결과 보고 형식으로 알려줘.」 | — |
| 7. 검토 | (아래 「검토할 때 볼 것」을 보고) 「`signals.md` ○번 줄은 근거가 약해. 원본을 다시 보고 확신도를 고쳐줘.」 | 고친 뒤 무엇이 달라졌나 |
| 8. 기록 | 「오늘 한 걸 `trend-agent/practice/worklog.md`에 5줄로 남겨줘: 지시 → 질문 → 중간 보고 → 고친 것 → 배운 것.」 | — |

**검토할 때 볼 것** — 결과 파일을 직접 열어서 확인해요.

- [ ] 표의 모든 줄에 근거 파일 이름이 있다
- [ ] 날짜나 출처가 빠진 스크랩을 Claude가 「확인 안 됨」으로 표시했다 (지어내서 채웠다면 다시 시키기)
- [ ] 확신도 「상」을 준 줄은 근거가 두 개 이상이다
- [ ] 반대 신호(안 될 수도 있다는 근거)를 빼먹지 않았다
- [ ] 고쳐달라는 지시를 **한 번 이상** 했다

> 💡 2단계에서 Claude가 물어본 질문은, 처음 지시에 빠져 있던 내용이에요. 다음 지시서에 그걸 미리 적으면 지시가 좋아집니다.

### 🛠 실전 — 내 자료로 한 바퀴 (1~2시간)

이번에는 **지시서를 직접 씁니다.** 연습 꾸러미의 `brief.md`를 본보기로 쓰세요.

| 할 일 | 이슈 |
|---|---|
| 내 소스 목록 `sources.md` | [#35](https://github.com/Dominic-DK/agent-study/issues/35) |
| 이번 주에 본 것 5개를 `raw/`에 | [#36](https://github.com/Dominic-DK/agent-study/issues/36) |

**1. 지시서 쓰기** — 「`@agent-study-blog/resources/w2-pack/wooju/brief.md`와 같은 형식으로, "내가 자주 보는 곳을 sources.md로 정리하는 일"의 지시서를 같이 쓰자. 칸마다 나한테 물어보고, 내 답으로 `trend-agent/brief-sources.md`를 만들어줘.」

**2. 소스 목록** — 「`@trend-agent/brief-sources.md` 대로 진행해. 인터뷰어처럼 한 번에 하나씩 물어보고, 3곳을 채우면 멈춰서 중간 보고해줘.」
- 「내 목표」에 적은 곳(구글 검색 · 캐릿 · 오픈서베이 · 데이터랩 · 인스타 · 유튜브)에서 시작
- 칸: 이름 · 종류 · 여기서 뭘 보나 · 얼마나 자주 · 믿는 정도 · 주소

**3. 스크랩 5개** — 이번 주에 실제로 본 것을 하나에 메모 하나씩. 「방금 본 걸 `trend-agent/raw/`에 메모로 남기자. `@agent-study-blog/resources/w2-pack/wooju/raw-sample/01-insta-reel.md`와 같은 칸으로. 날짜 · 어디서 · 주소 · 본 것 · 왜 저장했나를 물어봐줘.」
- 모아둔 스크랩이 없어도 괜찮아요. 오늘부터 쌓으면 됩니다
- 「왜 저장했나」 칸이 제일 중요해요. 인터뷰에서 꺼낸 판단 기준이 여기에 쌓입니다

**4. 올리기** — 「#35, #36에 결과 한 줄씩 남기고 닫아줘: sources 몇 곳, raw 몇 개.」 (`trend-agent/`는 내 컴퓨터에만 있어요. 사이트에는 올리지 않습니다)

### 💡 앞으로 — 트렌드 서치는 조금씩 맡기고, 기록은 매번 남기기 (추천)

이번 주부터 트렌드를 찾아볼 때 이렇게 해보길 권해요. 손으로 다 하던 것을 단계별로 Claude에게 넘기고, **찾아본 것은 매번 기록으로 남깁니다.**

| 단계 | 누가 찾나 | Claude에게 | 언제부터 |
|---|---|---|---|
| 수동 | 내가 보고, 메모만 맡긴다 | 「방금 본 걸 `trend-agent/raw/`에 메모로 남기자」 | 이번 주 (스크랩 5개) |
| 반자동 | 주제와 볼 곳은 내가 정하고, 찾아서 정리하는 건 맡긴다 | 「`@trend-agent/sources.md`에 있는 곳 중 2곳에서 "○○" 관련 최근 글을 찾아서 `raw/`에 메모로 남겨줘. 찾은 주소를 꼭 적고, 못 찾으면 못 찾았다고 말해줘.」 | 이번 주에 한 번 해보기 |
| 자동 | 정해 둔 곳을 정해 둔 주기로 Claude가 훑는다 | 스킬 · 예약 실행으로 | W3 이후 같이 만들어요 |

**기록은 `trend-agent/search-log.md`에 한 줄씩 남깁니다.**

> 「오늘 찾아본 걸 `trend-agent/search-log.md`에 한 줄 추가해줘: 날짜 · 찾은 주제 · 본 곳 · 남긴 메모 파일 · 내 판단(신호다 / 아니다 / 모르겠다).」

- 기록이 쌓이면 「언제 무엇을 보고 어떻게 판단했나」가 남아요. 나중에 규칙을 고치고 백테스트 정답지를 만드는 재료가 됩니다
- 맡기는 범위가 넓어질수록 확인이 중요해요. Claude가 찾아온 주소는 직접 열어서 실제로 있는 글인지 봐주세요
- 인스타 · 유튜브처럼 로그인이 필요한 곳은 Claude가 못 볼 수 있어요. 그런 곳은 내가 보고 메모만 맡깁니다

- wiki 구조 잡기는 W3에 합니다. 이번 주는 소스와 스크랩까지예요
- 0단계 인터뷰도 이번 주에 있어요. 날짜는 디스코드에서 정합니다

## 🛠 동균 {#donggyun}

> W1에 pgvector에 3,000청크를 넣고 검색 · 채팅까지 돌려봤어요. 이번 주는 더 쌓지 않습니다. **① 데이터가 머무는 자리를 정하고 ② 지금 점수를 재고 ③ 그 재는 일을 에이전트에게 통째로 맡겨 봅니다.** 고치는 건 점수가 나온 다음이에요.

**순서가 중요합니다. 1번을 끝내기 전에는 읽을거리와 자료 폴더를 열지 마세요.**

### 1. 먼저 답하기 (30분) · [#33](https://github.com/Dominic-DK/agent-study/issues/33)

이슈 #33의 질문 네 개에, **지금 생각대로** 댓글을 남깁니다.

- 읽을거리와 자료에는 답의 방향이 들어 있어요. 그래서 읽기 전에 본인 생각을 먼저 적습니다
- 틀려도 괜찮고, 「아직 안 정했다」도 답이에요. 읽은 뒤에 무엇이 달라졌는지가 이번 주의 수확입니다

### 2. 읽기 (15분)

- **[데이터가 흐르는 길](https://claude.ai/artifact/Mh5aZRxf91i2hSNbuDBp7j)** — 수집한 데이터가 돌아갈 길, 데이터가 머무는 세 자리, 검색이 특정 문서를 못 찾을 때 보는 순서, 기준 점수 재기, 일을 통째로 맡기는 순서
- 읽고 나서 한 줄: 「내 구조에서 지금 빠져 있는 화살표는 ○○이다」 → 일요일 진행 로그에

### 3. 설계 정리 — 데이터가 머무는 자리 (1~2시간) · [#33](https://github.com/Dominic-DK/agent-study/issues/33)

```
agent-study-blog/resources/w2-pack/donggyun/
├── data-map.md              ← 자료 지도 · RAG 목적 카드 · 경로 그림
├── eval-sheet.md            ← 평가표
├── issue-eval-script.md     ← 이슈 본문 예시
├── issue-run.md             ← 맡기는 순서 + 시간 기록표
└── retrieval-diagnosis.md   ← 검색 실패 진단 순서 (SQL 포함)
```

1. Claude에게 지금 상태부터 조사시킵니다.

   > 「`@agent-study-blog/resources/w2-pack/donggyun/data-map.md`의 자료 지도 표를 같이 채우자. 먼저 내 저장소의 인제스트 코드와 문서 폴더를 읽고, 자료 종류별로 "지금 어디에 있나"와 문서 수를 조사해서 보여줘. "어디에 두는 게 맞나" 칸은 비워 둬. 그건 내가 정할게.」

2. 「어디에 두는 게 맞나」 칸은 **직접** 채웁니다. 읽을거리의 세 자리(RAG / 그때 검색 → 편입 / API 도구)를 기준으로.
3. RAG 목적 카드 다섯 칸을 채웁니다. 「넣지 않는 것」을 먼저 쓰세요.
4. 새 데이터의 경로를 그림으로 그립니다. 손그림 사진도 좋아요.
5. #33에 **두 번째 댓글**로 올립니다. 1번에서 쓴 답과 무엇이 달라졌는지 한 줄을 같이.

- ✅ **확인**: 자료 지도에서 「지금」과 「맞나」가 다른 줄이 몇 개인지 말할 수 있다

### 4. 측정 + 맡기기 — 기준 점수를 이슈 흐름으로 재기 (4~5시간) · [#37](https://github.com/Dominic-DK/agent-study/issues/37)

A(개발 워크플로 1~4단계)와 B(평가)를 한 번에 합니다. 「기준 점수를 재는 스크립트」를 이슈로 만들고, 그 이슈를 Claude에게 통째로 맡겨요.

**4-1. 정답 문서 정하기 (직접, 1시간)**

`eval-sheet.md`를 복사해서, 평가 질문 10개(#16)마다 「답이 들어 있는 문서와 쪽」을 직접 찾아 적습니다.

- 이 단계는 Claude에게 맡기지 않아요. 정답지를 만든 쪽이 채점도 하면 점수를 믿을 수 없습니다
- 숫자를 묻는 질문은 「도구 질문」으로 표시하고 인덱스 점수에서 뺍니다 (3번의 자리 구분과 이어져요)

**4-2. 이슈 올리기 (15분)**

`issue-eval-script.md`를 본인 저장소에 맞게 고쳐서 이슈로 올립니다. W1에 연습한 「요구사항 · 완료 조건 · 확인할 점」 형식 그대로예요.

**4-3. 맡기기 (2~3시간)**

`issue-run.md`의 순서를 따릅니다. 시작하기 전에 기록표에 시작 시각부터 적으세요.

| 단계 | 내가 멈춰서 볼 것 |
|---|---|
| 1. 이슈 읽기 | Claude가 정리한 요구사항이 내 의도와 같은가 |
| 2. 실패하는 테스트 | **멈춤.** 테스트가 완료 조건을 하나씩 검사하는가 |
| 3. 수정 | 테스트 파일을 건드리지 않았는가 |
| 4. 확인 | **바뀐 코드를 직접 읽는다** |

- 정해 둔 두 곳(2단계 뒤, 4단계) 말고 중간에 끼어든 횟수를 셉니다. 왜 끼어들었는지가 다음 지시를 고치는 재료예요
- 5~6단계(PR · 이슈 반영)는 W3에 합니다

**4-4. 재기 (30분)**

스크립트를 돌려서 `eval-sheet.md`의 「측정 1 — 기준」을 채웁니다.

- ✅ **확인**: 「검색형 ○/6, 심화형 ○/4」를 말할 수 있고, 기록표에 한 줄이 있다

### 5. (여유 있으면) 진단 — 원인 하나 찾기 (2시간) · [#38](https://github.com/Dominic-DK/agent-study/issues/38)
