## 📈 우주 {#wooju}

> 트렌드 탐색, 도메인 선정, 점수화는 이번 주 범위에서 제외합니다.

### 🧰 실무 상황 과제 — 팀 자료실 구축 (1시간) · [#39](https://github.com/Dominic-DK/agent-study/issues/39)

입사 3주 차입니다. 지난주 회의에서 활용한 신호 표를 두고 옆 팀에서 문의가 왔습니다. 「이 신호를 처음 확인한 날이 언제인가요? 반대 의견은 없었나요?」 표 작성자가 휴가 중이어서 아무도 답하지 못했고, 팀장은 담당자가 없어도 확인할 수 있는 자료실을 만들어 달라는 이슈를 등록했습니다.

```
agent-study-blog/resources/w3-pack/wooju/
├── brief.md               ← 업무 지시서
├── page-format.md         ← 자료실 페이지 형식
├── excerpt-format.md      ← 예전 기록 발췌 형식 (실전 2)
└── reflection-format.md   ← 돌아보기 형식 (실전 3)
```

W2의 가상 스크랩 6건(`w2-pack/wooju/raw-sample/`)을 다시 사용합니다. 같은 자료를 표로 정리했을 때와 자료실로 정리했을 때의 차이를 비교해 보세요.

| 단계 | Claude에게 요청할 내용 | 확인할 사항 |
|---|---|---|
| 1. 지시 전달 | 「`@agent-study-blog/resources/w3-pack/wooju/brief.md`를 읽고 이해한 내용을 5줄로 설명해 줘. 작업은 아직 시작하지 마.」 | 의도한 업무와 일치하는가 |
| 2. 질문 | 「시작하기 전에 확인할 사항을 한 번에 하나씩 질문해 줘. 질문이 끝나면 "질문 끝"이라고 알려 줘.」 | W2와 비교해 질문이 어떻게 달라졌는가 |
| 3. 작성 규칙 | 「`@agent-study-blog/resources/w3-pack/wooju/page-format.md`를 참고해 `trend-agent/practice/library/CLAUDE.md`에 작성 규칙 6개를 기재하고 멈춰 줘.」 | 규칙 6개의 뜻을 직접 설명할 수 있는가 |
| 4. 1건 등록 | 「`@agent-study-blog/resources/w2-pack/wooju/raw-sample/01-insta-reel.md`만 등록해 줘. 작성할 페이지를 먼저 알려 주고, 내가 확인하면 작성한 뒤 멈춰 줘.」 | 「저장 이유」가 원문과 일치하는가 |
| 5. 나머지 등록 | 「나머지도 한 건씩 등록하고, 건마다 작성한 페이지와 수정한 페이지를 한 줄로 알려 줘.」 | 기존 페이지도 수정했는가 |
| 6. 질문하기 | 「wiki에 있는 내용만으로 답하고 문장마다 근거 파일을 표기해 줘. ① 들깨 라떼의 최초 확인일은? ② 반대 신호는? ③ 자료실에 없어 답할 수 없는 내용은?」 | 근거 파일에 해당 내용이 있는가 |
| 7. 점검 | 「근거가 없는 문장, 날짜가 없는 자료, 다른 페이지와 연결되지 않은 페이지를 표로 정리해 줘. 수정은 하지 마.」 | 직접 발견한 문제가 표에 포함됐는가 |
| 8. 수정 | 「표의 ○번을 다음과 같이 수정해 줘: …」 | 수정 전후가 어떻게 달라졌는가 |
| 9. 기록 | 「`trend-agent/practice/library/worklog.md`에 지시, 질문, 중간 보고, 수정 사항, 배운 점을 5줄로 기록해 줘.」 | — |

> 💡 4단계에서 「저장 이유」가 원문과 다르면 「저장 이유를 원문 그대로 다시 옮겨 줘」라고 요청하세요. 이후 돌아보기에서 본인의 판단을 확인하려면 원문이 필요합니다.

### 🛠 실전 1 — 내 스크랩을 wiki로 정리 (1시간) · [#40](https://github.com/Dominic-DK/agent-study/issues/40)

W2에서 작성한 `raw/` 메모 5건을 같은 방식으로 정리합니다.

1. 「`@trend-agent/practice/library/CLAUDE.md`를 참고해 `trend-agent/CLAUDE.md`에 내 wiki의 작성 규칙을 기재하자. 항목마다 질문하고 내 답을 반영해 줘.」
   - 연습에서 불편했던 점이 있으면 규칙을 추가하거나 제외합니다.
2. 「`@trend-agent/raw/`에서 메모 한 건을 선택해 wiki에 등록해 줘. 작성할 페이지를 먼저 알려 줘.」 결과를 확인한 뒤 나머지를 등록합니다.
3. 「wiki에 있는 내용만으로, 내가 반복해서 저장한 주제를 알려 줘. 문장마다 근거 파일을 표기해 줘.」
4. 직접 작성한 질문 2개를 추가로 묻고, 답변이 부정확하면 근거 파일과 대조합니다.

## 🛠 동균 {#donggyun}

> 지난주에는 기준 점수를 측정하고 이슈 1건을 에이전트에게 맡겼습니다. 이번 주에는 기능을 추가하지 않습니다. **① 결과를 직접 열어 보고 ② RAG와 Claude를 같은 자료로 비교하고 ③ 맡긴 이슈를 완료합니다.** 큰 문제를 나눠 한 번에 하나씩 진행합니다.

### 📏 지난주 채점 규칙 정정

- **심화형**: 자료에서 정한 「정답 문서가 전부 3위 안」은 적절한 기준이 아니었습니다. 「상위 10개 안에서 찾은 정답 문서 비율」로 변경합니다. 측정 1은 정답 문서 9건 중 7건입니다.
- **숫자 질문**: 1번과 2번은 별도로 집계합니다. 측정 1은 검색형 4/4, 숫자 질문 0/2입니다.
- **측정 2**: 「문서당 최대 3장」은 채팅이 이미 사용하는 방식이므로 실전 2의 결과로 대신합니다.
- 점수는 평가표에 기재한 순위로 다시 계산한 값입니다. 평가 스크립트는 수정하지 않아도 됩니다.

### 🔎 실전 1 — 결과 세 개를 내 말로 설명 (1시간) · [#44](https://github.com/Dominic-DK/agent-study/issues/44)

```
agent-study-blog/resources/w3-pack/donggyun/
├── three-results.md   ← 결과 설명 기록지 (실전 1)
└── compare-sheet.md   ← 비교 기록지 (실전 2)
```

두 파일을 본인 저장소로 복사해 사용합니다. **3번 → 1번 → 9번** 순서로 하나씩 진행합니다.

1. 검색 결과의 1위 카드와 정답 쪽을 나란히 엽니다.

- 설명이 막히면 「여기까지는 설명할 수 있고, 여기부터 모르겠다」라고 적고 다음 문항으로 넘어갑니다.

### ⚖️ 실전 2 — RAG와 Claude 비교 (1시간 30분) · [#45](https://github.com/Dominic-DK/agent-study/issues/45)

Claude가 더 잘 찾았다면 이유를 확인합니다. 찾는 방법이 달랐는지, 자료가 달랐는지 구분하려면 **같은 자료**로 비교해야 합니다.

**준비**

1. 번역본 10건만 새 폴더에 복사합니다. 정답지와 평가표가 있는 폴더에서 실행하면 Claude가 정답을 읽을 수 있습니다.
2. 질문 4개를 준비합니다. 3번(검색형), 1번(숫자), 9번(심화형), **답이 없는 질문 1개**입니다.
   - 답이 없는 질문은 직접 작성합니다. 번역본에서 관련 낱말을 검색해 내용이 없는 것을 확인한 뒤 확정합니다.
   - 6번 메모에 「코퍼스에 없음」으로 적은 자료에서 고르면 쉽습니다.

**비교** — 질문마다 새 대화에서 한 번씩 묻고 답변 전문을 저장합니다.

| 방법 | 요청 | 유의 사항 |
|---|---|---|
| ① 내 RAG 채팅 | 질문만 그대로 입력 | 다른 문장을 붙이면 검색에 쓰이는 문장이 달라진다 |
| ② Claude Code | 「이 폴더의 파일만 보고 답해 줘. 웹 검색은 사용하지 마. 문장마다 파일 이름과 쪽을 표기하고, 폴더에 없으면 "확인 안 됨"이라고 답해 줘. 마지막에 어떤 낱말로 몇 번 검색했는지 알려 줘. 질문: …」 | 준비한 폴더에서 실행. 앱의 Code 탭과 CLI 모두 가능 |
| ③ (선택) 지난번 방식 | 지난번에 Claude로 찾을 때와 동일하게 입력 | 웹 검색 사용 여부와 탭 이름을 기록 |

1. 정답 쪽을 직접 열어 ○ · △ · ✕로 판정합니다.
2. 두 방법의 모델 이름을 함께 적습니다. 모델이 다르면 결과에 그 차이도 섞입니다.
3. 기록지 아래에 두 줄을 작성합니다. 「결과가 달랐던 질문은 ○번이다. 이유는 …라고 생각한다.」

- 질문이 4개이므로 어느 방법이 더 좋다고 결론짓지 않습니다. 여유가 있으면 나머지 7문항도 기록합니다.
- 저장한 ①의 답변이 「출처 붙은 답변 v0」입니다. 문서명과 쪽이 표기됐는지만 확인합니다.
- ✅ **확인**: 결과가 달랐던 질문 하나를 골라 이유를 설명할 수 있다.

| 단계 | Claude에게 요청할 내용 | 확인할 사항 |

| 5. PR | 「`gh pr create`로 PR을 만들자. 요약, 바뀐 파일, 테스트 결과, 이슈 링크를 넣고, 만들기 전에 제목과 본문을 먼저 보여 줘.」 | 본문을 내 말로 설명할 수 있는가. **머지는 직접** |
| 6. 이슈 반영 | 「이슈에 남길 댓글을 작성해 줘. PR 링크와 결과를 넣고, 올리기 전에 먼저 보여 줘.」 | 다른 사람이 읽고 결과를 알 수 있는가 |
| 7. 스킬 | 「방금 진행한 5~6단계를 `/issue-finish` 스킬로 작성하자. 입력, 순서, 확인을 요청할 시점, 결과물을 `.claude/skills/issue-finish/SKILL.md`에 기재해 줘. 마지막에 "사람이 결과를 세 문장으로 설명할 때까지 기다린다"를 넣어 줘. 파일을 작성하기 전에 내용을 먼저 보여 줘.」 | 확인 시점에 실제로 멈추는가 |
| 8. 기록 | `issue-run.md` 기록표에 한 줄 추가 | 시작 · 끝 · 끼어든 횟수 |

커리큘럼에 있는 숫자 조회 도구와 `/issue-start`는 이번 주 범위에서 제외합니다. 실전 2의 결과를 보고 W4에서 필요한지 정합니다.
