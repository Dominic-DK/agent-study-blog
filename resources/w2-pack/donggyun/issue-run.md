# 이슈 1건을 맡기는 순서 (A 1~4단계)

단계마다 Claude에게 할 말과, 내가 멈춰서 볼 것입니다. `N`은 이슈 번호로 바꾸세요.

## 순서

| 단계 | Claude에게 | 내가 볼 것 |
|---|---|---|
| 0. 시작 | (기록표에 시작 시각 적기) | — |
| 1. 이슈 읽기 | 「`gh issue view N`으로 이슈를 읽고, 요구사항과 완료 조건을 네 말로 정리해줘. 애매한 점은 질문해줘. 아직 코드는 건드리지 마.」 | 정리한 내용이 내가 의도한 것과 같은가 |
| 2. 실패하는 테스트 | 「새 브랜치를 만들고, 완료 조건을 확인하는 테스트를 먼저 써줘. 구현은 하지 마. 테스트가 실패하는 것까지 보여주고 멈춰.」 | **여기서 멈춤.** 테스트가 완료 조건을 하나씩 검사하는가. 빠진 조건은 없는가 |
| 3. 수정 | 「이제 테스트가 통과하도록 구현해줘. 테스트 파일은 고치지 마. 막히면 멈추고 물어봐.」 | 테스트 파일이 바뀌지 않았는가 |
| 4. 확인 | 「테스트 전체를 돌리고, 바뀐 파일과 전후 차이를 요약해줘. 확신이 없는 부분도 적어줘.」 | **바뀐 코드를 직접 읽는다.** 요약만 보고 넘어가지 않기 |

- 5~6단계(PR 만들기 · 이슈에 반영)는 W3에 합니다. 이번 주는 브랜치에 커밋까지.
- 2단계에서 테스트가 마음에 안 들면 구현으로 넘어가지 말고 테스트부터 고치게 합니다.

## 기록표

6주 뒤 「전/후 시간 비교」에 쓰는 자료입니다. 이슈를 처리할 때마다 한 줄씩 남깁니다.

| 날짜 | 이슈 | 시작 | 끝 | 걸린 시간 | 내가 끼어든 횟수 | 손으로 했다면 (예상) | 메모 |
|---|---|---|---|---|---|---|---|
| 2026-11-22 | chainscout-ai#1 평가 질문 10개로 검색 기준 점수 재기 | 16:20 | 17:22 | 약 1시간 | 1 | 약 3일 | 2단계 보고가 영어로 와서 한국어로 다시 요청(끼어듦 1). 2단계 확인 지점에서 고친 것 2번: 문서 ID가 파일명으로 들어가 7번이 항상 「없음」이 될 뻔한 것을 DB doc_id로 수정, manifest에 CIMCE · BNDES가 없어 두 줄 추가(재인제스트는 안 함). 결과: 검색형 4/6, 심화형 0/4 |

- **끼어든 횟수**: 정해 둔 확인 지점(2단계 뒤, 4단계) 말고, 중간에 멈추게 하거나 방향을 고친 횟수
- **메모**: 어느 단계에서 왜 끼어들었는지. 이게 다음 지시를 고치는 재료입니다

## 잘 된 지시 모아두기

W3에 `/issue-start` 스킬로 만들 재료입니다. 잘 먹힌 문장을 그대로 붙여 두세요.

- 「`gh issue view N`으로 이슈를 읽고, 요구사항과 완료 조건을 네 말로 정리해줘. 애매한 점은 질문해줘. 아직 코드는 건드리지 마.」 → 1단계에서 질문 5개가 나와 정답지 · 분모 · 표시 형식 · 위치를 구현 전에 정함
- 「정답은 내가 정한 거니까 내용은 바꾸지 마.」 → 사람이 정한 데이터(정답지)를 Claude가 손대지 않게 함
- 「보고는 한국어로 해줘.」 → 지시 첫머리에 넣거나 저장소 `CLAUDE.md`에 적어 두기. 이번에 2단계 보고가 영어로 와서 다시 요청함(끼어듦 1)
- (이슈 본문) 「이번 이슈에서 하지 않는 것」 칸 → 검색 로직 수정 안 함, 설정 파일 안 엶 등을 적어 두니 1단계 정리에서 지킬 조건으로 그대로 옮겨 적음
- (이슈 본문) 「위치와 실행 방법은 1단계에서 제안받아 정한다」 → Claude가 선택지와 장단점을 내놓고, 결정은 내가 함
